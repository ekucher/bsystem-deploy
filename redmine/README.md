# Redmine runtime

This directory is the source-controlled deployment definition for the BSYSTEM
Redmine business service. Runtime secrets stay outside Git.

## Components

- Redmine 6.1.4
- PostgreSQL 17
- `kontron/redmine_oauth` 4.2.2 pinned to commit
  `69f9a2a7b4f64a6aa6b5ffb5e4161891395f3310`
- Authentik OIDC login
- Integration Core read-only access through a dedicated non-admin Redmine API
  service identity

## Local configuration

Create the secret file next to the Compose file:

```bash
cp redmine.env.example redmine.env
chmod 600 redmine.env
```

Replace every `CHANGE_ME` value. `POSTGRES_PASSWORD` and
`REDMINE_DB_PASSWORD` must contain the same database password.

`redmine.env` is ignored by Git and must never be committed.

Validate before starting or recreating anything:

```bash
docker compose --env-file redmine.env config -q
```

## Start

The BSYSTEM platform frontend network must already exist because Redmine joins
it so Integration Core can reach the service by Docker DNS.

```bash
docker compose --env-file redmine.env up -d --build
```

The browser-facing DEV endpoint is loopback-only:

```text
http://127.0.0.1:18103
```

For the current SSH-tunnel/OIDC development flow, use
`http://localhost:18103` in the browser. The Authentik callback is
`http://localhost:18103/oauth2callback`; starting the OAuth flow with
`127.0.0.1` makes Redmine derive a different callback host.

## Secret isolation

The database container receives only:

- `POSTGRES_USER`
- `POSTGRES_PASSWORD`
- `POSTGRES_DB`

The Redmine container receives only:

- `REDMINE_DB_POSTGRES`
- `REDMINE_DB_PORT`
- `REDMINE_DB_USERNAME`
- `REDMINE_DB_PASSWORD`
- `REDMINE_DB_DATABASE`
- `REDMINE_SECRET_KEY_BASE`
- `BSYSTEM_OIDC_CLIENT_SECRET`
- `REDMINE_PLUGINS_MIGRATE`

This separation is intentional. Do not replace it with a shared `env_file`
for both services.

## Persistence

The named volumes are:

- `redmine-postgres` — PostgreSQL data
- `redmine-files` — Redmine uploaded files

Do not use `docker compose down -v` for ordinary maintenance, deployment, or
upgrade work.

## Authentik

The tested DEV OIDC application/provider uses:

- application: `BSYSTEM Redmine`
- application slug: `bsystem-redmine`
- client ID: `bsystem-redmine`
- callback: `http://localhost:18103/oauth2callback`
- scopes: `openid profile email`
- PKCE: S256

The Authentik provider objects are deployment state and are not generated by
this Compose bundle yet. The client secret is supplied through
`BSYSTEM_OIDC_CLIENT_SECRET`.

## Integration Core

Integration Core connects server-to-server through the shared Docker network:

```text
REDMINE_URL=http://redmine:3000
```

Its API key belongs to the dedicated `bsystem-integration` Redmine account.
That account is non-admin and the tested service role contains only
`view_issues`. The Integration Core adapter is read-only and uses the
`X-Redmine-API-Key` header.

The API key belongs in the top-level deployment `.env`, not in
`redmine.env`.
